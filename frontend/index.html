Introduction

A model that can't explain itself is a liability. I build systems that show their work.

I'm Afzal Siddiqui, a machine learning engineer based in Lucknow, India, studying AI & ML at Integral University. My work sits where computer vision meets messy regulation — reading labels, extracting fields, and turning them into decisions a non-technical person can act on.

The flagship is ComplianceAI, built for Smart India Hackathon 2026: an engine that inspects a packaged product against 12 Legal Metrology rules, scores it out of 100, estimates the statutory penalty, and generates an official notice. I care about the unglamorous half of machine learning — preprocessing, calibration, explainability, and shipping the database, PDF and admin panel that make a model usable.

Computer Vision & OCR

Multi-pass preprocessing — de-skew, upscale, CLAHE contrast, adaptive threshold and denoise — before EasyOCR runs, then per-token confidence scoring and an Indian-packaging text normalizer.

  • EasyOCR extraction
  • Confidence scoring
02

Rule Engines & Scoring

Regulation encoded as testable predicates with severity weights, category-aware calibration and a deduction trace — so every score can be explained line by line.

  • Weighted rule engine

Lab Notes

01

Rules beat vibes

A regulation has twelve clauses. I encode each one as a testable predicate with a severity weight, so the output is a line-by-line explanation instead of a probability nobody can defend in an audit.

ExplainabilityLegal logic
02

OCR is a preprocessing problem

The first pass over Indian packaging is usually garbage. Fixing contrast, de-skewing and upscaling before the model runs bought a bigger accuracy jump than any model swap I have tried.

Computer visionSignal processing
03

Ship the boring parts
